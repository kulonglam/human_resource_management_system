# Deploy checklist — FCA HRMIS

Use this guide to sync **staging** and **production** on Render after pushing code changes.

## 1. Sync the Render blueprint

1. Open [Render Dashboard](https://dashboard.render.com) → **Blueprints**
2. Select the HRMIS blueprint linked to this repo
3. Click **Manual Sync** (or push to `main` if auto-deploy is enabled)
4. Confirm two web services and two databases are created:
   - `human-resource-management-system` (production)
   - `human-resource-management-system-staging` (staging)
   - `avvento-hrmis-db` / `avvento-hrmis-db-staging`

### Build command (required)

The React SPA must be built during deploy (`frontend/dist`). If you see:

`React frontend is not built. Run: cd frontend && npm install && npm run build`

your Render service is missing the frontend build step.

**Blueprint / `render.yaml` services** use:

```bash
bash scripts/render-build.sh
```

**Manually created services** — open Render → your web service → **Settings** → **Build Command** and set:

```bash
bash scripts/render-build.sh && python manage.py migrate --noinput
```

(or keep `migrate` in **Pre-Deploy Command** as in `render.yaml` instead of the build step).

## 2. Configure environment variables (both services)

Set these in the Render dashboard for **production** and **staging** separately.

### Required (auto-generated by blueprint)

| Variable | Notes |
|----------|-------|
| `SECRET_KEY` | Auto-generated |
| `DATABASE_URL` | Linked from database |
| `SEED_*_PASSWORD` | Auto-generated; save admin password securely after first deploy |

### Security (defaults in blueprint)

| Variable | Production | Staging |
|----------|------------|---------|
| `DEBUG` | `False` | `True` |
| `ALLOW_PUBLIC_REGISTRATION` | `False` | `False` |
| `ENFORCE_MFA_FOR_ADMINS` | `True` | `True` |
| `RENDER_SERVICE_NAME` | `production` | `staging` |

### SMTP (required for email notifications)

| Variable | Example |
|----------|---------|
| `EMAIL_BACKEND` | `django.core.mail.backends.smtp.EmailBackend` |
| `EMAIL_HOST` | `smtp.sendgrid.net` |
| `EMAIL_PORT` | `587` |
| `EMAIL_HOST_USER` | `apikey` |
| `EMAIL_HOST_PASSWORD` | *(your SMTP password)* |
| `EMAIL_USE_TLS` | `True` |
| `DEFAULT_FROM_EMAIL` | `noreply@yourdomain.com` |
| `HR_NOTIFY_EMAIL` | `hr@yourdomain.com` |

Without SMTP, emails are dropped silently when no recipients/backend is configured (console backend in local dev only).

### Sentry (recommended for production)

| Variable | Example |
|----------|---------|
| `SENTRY_DSN` | `https://…@….ingest.sentry.io/…` |
| `SENTRY_TRACES_SAMPLE_RATE` | `0.1` |

Leave `SENTRY_DSN` unset on staging if you prefer a separate Sentry project per environment.

### SSO (optional)

| Variable | Notes |
|----------|-------|
| `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` | Google Workspace / Google Cloud OAuth app |
| `MICROSOFT_OAUTH_CLIENT_ID` / `MICROSOFT_OAUTH_CLIENT_SECRET` | Azure AD app registration |
| `MICROSOFT_OAUTH_TENANT` | Azure tenant ID or `common` (default) |
| `SSO_CALLBACK_BASE_URL` | Public backend URL, e.g. `https://your-service.onrender.com` |
| `SSO_FRONTEND_REDIRECT` | Post-login SPA URL, e.g. `https://your-service.onrender.com/dashboard` |
| `SSO_AUTO_PROVISION` | `False` (default) — users must already exist in HRMIS |

Register OAuth redirect URIs:
- Google/Microsoft callback: `{SSO_CALLBACK_BASE_URL}/api/v1/auth/sso/{google|microsoft}/callback/`

### S3 media (optional)

| Variable | Notes |
|----------|-------|
| `AWS_STORAGE_BUCKET_NAME` | Enables S3-backed `MEDIA_ROOT` |
| `AWS_S3_REGION_NAME` | e.g. `us-east-1` |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | Omit on AWS if using instance/task IAM role |
| `AWS_S3_CUSTOM_DOMAIN` | Optional CDN domain for media URLs |

## 3. Verify deployment

After deploy completes:

```bash
# Health check (no auth)
curl https://<your-service>.onrender.com/api/v1/health/
# Expected: {"status":"ok","database":"ok","version":"1.0.0"}

# Login via SPA, enable admin MFA at /settings/security
```

## 4. Staging → production workflow

1. Push changes to `main`
2. Staging deploys first (same branch) — smoke test:
   - Login + MFA setup
   - Create leave / expense / appraisal
   - Check audit log at `/audit-logs`
   - Confirm emails arrive (if SMTP configured)
3. Production auto-deploys from the same push (or promote manually)
4. Re-check health endpoint and admin MFA on production

## 5. Rollback

In Render → service → **Deploys** → select a previous successful deploy → **Rollback**.

## 6. Local pre-deploy checks

```powershell
pip install -r requirements.txt
python manage.py check
python manage.py test api
coverage run --source=api manage.py test api
coverage report --omit="api/tests/*"
cd frontend ; npm run build
```

CI enforces **≥60%** API coverage (see `.coveragerc` and `.github/workflows/ci.yml`).
